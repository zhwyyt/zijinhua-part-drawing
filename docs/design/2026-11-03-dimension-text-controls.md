# 短尺寸文字控制对照试验

承接可见笔画验证：三规格20个箭头被文字白遮罩削边。本轮目标是确定公开原生属性能否保持文字、线和箭头完整，不通过缩字/缩箭头或伪造尺寸值解决。

## 已确认的API边界

本机Tekla 2017公开属性反射及XML：DimensionTextAttributes只有Font、Frame、TextPlacing；TextPlacing支持AboveDimensionLine/OnDimensionLine。ShortDimension支持Inside/Outside。Placing.Distance公开MinimalDistance/SearchMargin，但它是放置搜索属性，不能预先当文字间隙。StraightDimension没有公开文字坐标/偏移属性。禁止写内部结构、改全局选项或用隐藏原尺寸文字叠加替代文字掩盖问题。

## 计划与验收

1. 最小扩展独立新页探针：可选textPlacing和成对minimalDistance/searchMargin，省略仍保持旧请求行为；采集实际父集属性、子值、显示原语，保持原锚点/字高/实心箭头尺寸。
2. 复用当前584已验证资产，在三规格新登记页做Above/On、Inside/Outside与跨度/字高0.5、1、2对照；另对相同短尺寸增加放置间距对照。所有试样仍为合成sheet坐标，不代表真实视图尺度。
3. 两次保存重开、PDF字形绑定、原语核验、可见裁剪及箭头损失测量，局部渲染验证。只把实际可保持完整性的配置记为有限证据，属性读回通过而图面无效必须记录失败。未成功则明确公开接口能力缺口，不再靠猜字段堆规则。

本轮只创建新登记测试页，保留已有18页/84份资产及305/584验收页、101人工标注。创建前核对现场连接、模型身份、fresh来源、无活动图、资产哈希和台账；目标页号由当前登记后续有限编号请求，已占用插入失败即停，不枚举全目录。完成后核对原属性全清单、既有登记、来源及原125文件，相关回归/C#编译/全量unittest与文档记录。

## 对照后追加：按实际模板尺寸字段验证候选样式

20/21/22页的72项文字控制对照证明，0.8字高箭头下这些控制没有统一解决最短尺寸；图10的On/Inside/跨度2还出现约97%箭头遮蔽。原模板实例快照同时确认：10/20/50的实际Arrowhead.Height/Width为10/20/50，文字高25/50/125，即0.4字高；原Head是NoArrow、字体romsim。因此不能把之前人工指定的0.8压力试样等同于实际模板样式。

追加有限三页（23/24/25）验证：从当前模板快照读取箭头尺寸，保留用户已要求的FilledArrow和前轮已核验的仿宋，保持字高及数值锚点；不是把原模板NoArrow/romsim整套直接宣称合格。探针新增成对可选arrowHeight/arrowWidth，缺省仍为0.8字高，实际尺寸必须在SDK和PDF三角形同时读回；旧失败证据不重写。跨度/字高0.5、1、2、4、8覆盖Inside/Outside，并带直/折引线。记录尺寸字段的原快照/哈希和明确覆盖项，不能通过任意缩小箭头寻找通过值，也不直接发布生产字体/箭头策略。
