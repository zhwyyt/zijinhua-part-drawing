# 原生零件图规划层架构

- 日期：2026-10-21
- 状态：结构性决定已于 2026-10-21 全部评审确认（见第 9、10 节）；已按下述里程碑分阶段实施。实施进度：M0 基线、M1 拆层、M2 去纸面单位、M3a 口径配置与可读性门、M3b 轮廓边到边成链与门阻断已完成（见 M0、M1、M2、M3a、M3b）；M4 已实现实时模板采集及 P4 接入，当前自有图现场保存重开/SDK/DXF验收通过，见M4实现。
- 分支：`exp/tekla-native-part-drawing`，代码核对基线 `884f6da`。
- 范围：单视图保持 `expressionRequirements.v1` → `nativeDrawingPlan.v1`。2026-10-26 厚度坡口扩展为 v2 多视图要求/计划/读回，见[剖面分层设计](2026-10-26-native-sections.md)；读取器、几何审计、加工表达要求、C# 写图器和保存重开读回保持各自职责。

## 1. 为什么要重做这一层

现有规划由 `native_layout.build_layout`（约 290 行）和 `native_dimensions` 完成。它在一个函数里同时决定"标什么"和"摆哪里"，没有中间产物：

- 没有显式的标注方案。基准、尺寸组用途、链式/坐标式、有意冗余都只隐含在代码分支里。用户只能看最终图挑错，每次反馈只能变成一条新规则。R2→R2.3 四轮都在 P-116 上补规则、去冗余，R2.3 还推翻了 R2.1 保留 120 的决定。
- 选择受纸面单位影响。`short_run = any(v/scale < 12)` 会让整条轮廓链改成逐段局部尺寸；孔链在 `/scale < 7` 时退化为逐孔基准尺寸。比例一变，标注内容就变。
- 质量门只证明"可确定"。`expression_coverage` 把尺寸视为每个方向上的连通图，连通即 `PLAN_COMPLETE`；要做减法、无说明冗余、基准不一致、层数过多都发现不了。
- 布局是固定候选的贪心算法，没有回溯；图框和标题栏不参与（写图器在 C# 里写死底部预留 45 mm）。

离线分支已有可复用的设计思路：尺寸规划层 的 Generator→Planner→Optimizer 分层和"布局不得增删尺寸"，以及 `codex/offline-part-drawing-engine` 上 R1 评审稿的"需求先行、硬条件优先于美观、有界反馈"。原生路线实现了需求与覆盖门，但没有落实规划与布局分离。本设计沿用这些原则，不合并离线分支代码。

## 2. 设计原则

1. **先方案，后纸面。** 标注方案只使用模型毫米和真实锚点，不出现比例、纸面毫米和文字尺寸。同一零件在任何比例下方案相同。
2. **方案是可评审对象。** 方案能以人能读的清单形式输出；用户反馈先落到方案口径或案例上，再改代码。
3. **决策可解释。** 每个基准、每组尺寸都记录由哪条规则、依据哪项特征选出，以及排除了哪些候选。
4. **工程正确是硬条件，可读性是可检查的门，美观是软目标。** 不用布局评分抵消漏标或错标。
5. **布局不改方案。** 布局只决定位置；放不下时在声明的范围内调整视图、比例和候选，或返回失败，不得删除、合并或新增尺寸。
6. **口径与算法分离。** 基准策略、链式/坐标式、冗余口径、组合规则等写在版本化的口径配置里；算法读取配置，不在分支里写死。
7. **平局按几何语义裁决。** 不以 `vertex:9` 这类 ID 字符串排序决定工程选择；ID 只作最后的确定性兜底，并记入决策日志。

## 3. 分层

```text
expressionRequirements.v1 + nativeGeometryAudit（frame / finalOutline）
  │
  P1 特征模型        facts → PlateFeatureModel（基准候选、轮廓特征、孔型、R/切角）
  │
  P2 标注方案        PlateFeatureModel + 口径配置 → DimensionScheme（无纸面单位）
  │
  P3 方案门          完整性（复用 expression_coverage）+ 可读性门
  │                  ── 失败：BLOCKED，指出规则和特征，不进入布局
  P4 视图与图幅      DimensionScheme + 图纸模板配置 → ViewPlan（视向、比例、图幅、可用区）
  │
  P5 布局求解        DimensionScheme + ViewPlan → PlacedDrawing（纸面位置）
  │                  ── 失败：在预算内回到 P4 换比例/图幅；仍失败则 LAYOUT_OVERFLOW
  P6 输出            PlacedDrawing → nativeDrawingPlan.v1（写图器契约不变）+ PLAN 观测
  │
  写图 / 保存重开 / READBACK（现有）+ 方案一致性检查（新增）
```

### P1 特征模型 `plateFeatureModel.v1`

把原始点、段、孔整理成工程特征。现在 `contour_chains`、`tangent_straights`、`hole_datums` 在规划中途隐式完成这项工作，这里改为独立、可测试的一层。

| 特征 | 内容 | 来源 |
|---|---|---|
| 基准候选 | 真实外轮廓直边、对称轴、孔心；各自的轴向、跨度、覆盖范围 | 轮廓段 |
| 轮廓特征 | 每个方向的单调段、台阶/肩、相切直段、R 过渡、凹缺口、直线切角及其相邻关系 | 轮廓段与弧 |
| 孔型 | 单孔、单排、单列、完整正交孔阵、错列、不规则；同排/同列成员、间距是否相等 | 孔与孔组 |
| 外形 | 是否整圆、矩形、一般多边形；包络极值点及其所属段 | 轮廓 |

要求：每个特征带 `sourceRefs`；无法归类的几何直接列为 `UNCLASSIFIED`，由 P3 阻断，不在 P2 里猜测。孔型识别按"排"组织，避免当前把所有孔坐标去重后并成一条链。

### P2 标注方案 `dimensionScheme.v1`

P2 由特征处理器和方案组装器组成：

- **特征处理器**：每类特征一个，读取口径配置，给出该特征的标注意图（需要哪些尺寸、建议基准、可接受的表达方式）。
- **方案组装器**：选定每个方向的基准，合并共享坐标，确定尺寸组的用途和层级，登记有意冗余，并写决策日志。

契约草案：

```text
DimensionScheme
- conventionProfile: {id, version}
- datums[]: {id, axis, role: PRIMARY|LOCAL, kind: EDGE|AXIS|HOLE_CENTER, anchor, feature,
             locatedBy: 连接主基准的尺寸组 ID（LOCAL 必填）, reason}
             每个方向恰好一条 PRIMARY（包络低端极值边）；口径 v1 的 LOCAL 只允许
             对侧极值边（由总尺寸定位），内部肩边、孔心不作基准
- groups[]:
    id, axis
    purpose: OVERALL | BODY | CONTOUR_SEGMENT | TANGENT_FLAT | HOLE_EDGE | HOLE_PITCH | REFERENCE
    style:   CHAIN | ORDINATE | COMBINED_PITCH
    datum, anchors[]（真实点 ID，按测量方向排序）
    side:    {preferred, allowed[], locked}；语义侧（+X/-X/+Y/-Y），不是纸面坐标
             OVERALL 组与同列组 locked=true；孔定位、局部肩宽可声明两侧
    tier:    FEATURE < BODY < OVERALL（语义层级，决定由内到外）
    column:  同列分组 ID（例如被圆角断开的同一轮廓链）
    reference: null | {category: OVERALL|BODY|SYMMETRIC, reason}（有意保留的冗余；口径 v1 允许这三类，SYMMETRIC 为对称两侧重复）
    covers[]: 覆盖的需求 ID
    alternatives[]: 有序备选表达（如 CHAIN→ORDINATE）；口径 v1 不启用，恒为空
- callouts[]: {id, kind: HOLE_GROUP|RADIUS|DIAMETER|CHAMFER, targets[], text, anchorRule}
- annotations[]: 零件号（材料内空白）、厚度（表格/视图说明）、规格
- decisions[]: {rule, subject, choice, rejected[], basis}
- issues[]
```

P2 禁止使用 `scale`、纸面毫米、文字尺寸。"短"只能按模型尺寸和口径定义，并且只影响 P5 的排版方式，不影响 P2 选择。

### P3 方案门

1. **完整性**：把方案转成 PLAN 观测，交给现有 `audit_expression_coverage`，规则不变。
2. **可读性门**（新增），由口径配置驱动，初始检查项：

| 代码 | 检查 | 依据 |
|---|---|---|
| `RD_DERIVED_LENGTH` | 口径要求直接读取的加工长度只能靠加减得到；口径 v1 不要求相切直段直接读数（由 R 与定位推出） | 车间图口径修订 |
| `RD_UNDECLARED_REDUNDANCY` | 同一方向存在闭合尺寸环，且环中没有口径允许类别的 `REFERENCE` 组 | 第 3 项确认；解决 R2.1/R2.3 关于 120 的反复 |
| `RD_LOCAL_DATUM_UNLOCATED` | 局部基准没有由主基准出发的尺寸直接定位 | 第 2 项确认 |
| `RD_DATUM_SPREAD` | 同一方向主基准不唯一，或使用了口径不允许的局部基准（v1 只允许对侧极值边） | 第 2 项确认；车间图口径修订 |
| `RD_TIER_ORDER` | 层级颠倒，例如板身宽在孔定位内侧 | R2.1 |
| `RD_SPLIT_COLUMN` | 同一轮廓链拆出的分段没有共用列 | R2.3 |
| `RD_SCALE_DEPENDENT` | 同一输入在不同比例下方案摘要不同（测试级不变量） | 原则 1 |

可读性门不阻止完整性检查；两类失败分别报告。新口径先在这里加一条可测的检查，再改 P2。

### P4 视图与图幅

- 输入：方案、几何和**图纸模板快照**（图框、标题栏、表格占用区、各候选图幅的可用区）。快照在每次出图批次中从 Tekla 实时采集（第 6 项确认），写入批次证据；P4 只读快照，不直接连 Tekla，因此可离线回放和测试。比例系列、字高和箭头仍为口径/样式配置。
- 模板快照记录属性文件名、采集方式、各图幅的占用区和来源证据；采集失败则该批次阻断，不回退到写死的预留值。
- 输出：视向（第一阶段仍为 DSTV 主面，但作为显式选择记录）、比例、图幅、视图可用区。
- 比例：车间交付图为 1:1 模板（见第 10 节“1:1 交付模板”），口径 v1 固定比例 1:1、图幅取模板值，P4 不再选比例；放不下时的重试只剩视图位置与模板允许的图幅。
- 写图器的底部 45 mm 预留改由计划传入，C# 不再自定预留。
- 2026-10-26：经独立终态核验的整边平面坡口，由表达层声明强制剖面；P4 为主图/剖面分配独立 1:1 可用区，P5 不能删除剖面换取布局通过。普通详图仍留扩展点。

### P5 布局求解

- 输入：方案、视图计划。输出：每个尺寸组的纸面列坐标（Distance/Up）、界线缩短、文字与引线位置、零件号和说明位置。
- 硬约束：文字不重叠、线不穿字、引线不跨尺寸线或界线、在可用区内、不进标题栏、层级顺序与方案一致、同列组整体移动。
- 软目标：引线短、标注靠近特征、层间距紧凑、位置稳定。
- 算法：每个对象生成有序候选，按确定顺序放置；冲突时有界回溯（限定步数），并记录使用的预算。仍失败时，先回到 P4 尝试下一个比例或图幅，再失败返回 `LAYOUT_OVERFLOW` 和具体对象。
- 侧别：只能在方案声明的 `allowed` 中选择，`locked` 组不得换侧；实际选择写入布局报告。
- 禁止：增删或合并尺寸组、改锚点、改值、改层级、改同列关系、改 `n@p` 组合。方案若声明了备选表达（例如坐标式代替密集链式），P5 只能按声明顺序选用，选用后重跑 P3。

### P6 输出与读回

- 继续输出 `nativeDrawingPlan.v1`，写图器基本不变；计划中增加 `schemeDigest`、`viewPlan` 和布局报告。
- 每件都输出人能读的方案清单（基准、尺寸组、参考尺寸、说明、决策理由），不含纸面位置；清单不阻断出图。
- 重画同一零件时，清单附与上次已确认方案的变化对比（尺寸组增删、基准变化、参考类别变化）。用户确认后的方案摘要记入所有权登记，确认本身不阻断出图。
- 读回除现有覆盖与图面检查外，新增**方案一致性**：实际尺寸组的锚点、层级顺序和同列关系与方案一致。

## 4. 口径配置与案例库

### 口径配置 `conventions/flat-plate.<version>.json`

只放会影响方案选择的工程口径。每一项都要有用户确认来源，例如：

- 基准策略：主基准取包络低端极值边，局部基准允许的范围（v1：仅对侧极值边）。
- 轮廓与孔的标注方式：链式、坐标式或按条件混用。
- 冗余口径：哪些冗余作为参考尺寸保留（如板身宽、总尺寸），显示方式。
- 直接读数：哪些长度必须直接标出（v1：相切直段不要求）。
- 组合：几段以上等距合并为 `n@p`（v1：3 段起），两端边距是否独立。
- 显示精度（v1：整数）与孔显示方式（v1：Tekla 螺栓符号）。

口径变更须同时更新配置版本、设计记录和案例，不能只改代码。

### 案例库 `tests/fixtures/planning_cases/<case>/`

每个案例包含：

- 输入：`facts`（可由现场证据裁剪），不含零件号依赖。
- 期望：**方案级断言**，用工程语言描述，例如"右侧同一列：110｜间隔｜66、30；外层总高 216；不存在 120"。不断言纸面坐标。
- 归因：按 AGENTS.md 四类（数据、特征缺失、评分/口径、新类型）记录。
- 变体：换编号、缩放、旋转、镜像，证明不依赖编号或方向。

第一批回归案例取自 8 件已逐点对照的车间零件图（见车间图口径修订）。P-116 的 R2.1～R2.3 反馈按修订后的口径重新评估，其中与车间口径冲突的部分（局部基准、相切直段直接读数）不再作为期望。

## 5. 新特征类型的扩展方式

新增一类特征（例如直线切角、长圆孔阵、凹缺口）需要四件事，缺一不可：

1. P1 识别器及其 `sourceRefs`、反例；
2. P2 特征处理器及所需口径项；
3. P3 完整性规则（如需新需求类型）和可读性检查；
4. P5 的说明或引线候选（如需新的说明形式）。

不支持的类型在 P1 标为 `UNCLASSIFIED`，只阻断受影响零件。

## 6. 现有问题归位

| 现有问题 | 归属层 | 处理 |
|---|---|---|
| 没有标注方案，规则堆叠 | P2 | 引入 `dimensionScheme.v1` 和决策日志 |
| 覆盖门只验连通 | P3 | 增加可读性门 |
| 比例影响选择（`short_run`、孔链 `/7`） | P2/P5 | P2 去掉纸面单位，短尺寸只在 P5 排版 |
| 孔链不按排组织 | P1 | 孔型识别按排/列/阵 |
| 基准各管各 | P2 + 口径 | 每方向显式基准，按口径选择 |
| 只有正交投影、视向固定 | P1/P4 | 第一阶段保持；切角、对齐尺寸作为新特征类型扩展 |
| 固定候选贪心、无回溯 | P5 | 有序候选 + 有界回溯 + 回到 P4 |
| 图框标题栏不参与，C# 写死 45 mm | P4 | 图纸模板配置，由计划传入 |
| ID 字符串裁决平局 | P1/P2 | 几何语义裁决，ID 只兜底并记录 |
| 测试样本窄 | 案例库 | 方案级断言 + 变体 |
| 单函数难审查 | 全部 | 按层拆模块，每层独立测试 |

## 7. 迁移步骤

每一步都可单独回归，现场 Tekla 写图放在最后。

| 步骤 | 内容 | 验收 |
|---|---|---|
| M0 | 冻结现状：七件历史证据的当前 PLAN 存为基线快照。快照只用于比较差异，不代表正确 | 快照可重复生成 |
| M1 | 定义 P1/P2 契约，把现有逻辑原样拆入特征模型和方案（含 `short_run` 现状），P5 暂时复用现有放置代码 | 七件 PLAN 与基线一致；完整回归通过 |
| M2 | 去掉 P2 中的纸面单位，短尺寸处理移入 P5 | 差异逐件列出并说明；`RD_SCALE_DEPENDENT` 不变量测试通过。拥挤件允许转为 `LAYOUT_OVERFLOW`（已确认），溢出件不出图，只报告溢出对象，待 M5 改进 |
| M3 | P3 可读性门 + 车间图 8 件案例 + 口径配置 v1（按车间图口径修订） | 8 件案例的方案与车间图尺寸组一致；P-116 按新口径重新评估 |
| M4 | 先做只读 API 探测，确定模板快照采集方式；再实现批次内实时采集、P4 读快照，写图器预留由计划传入 | 探测记录写入 verification；现场一张自有图保存重开、读回通过 |
| M5 | P5 有界回溯布局（2026-10-23完成约定范围，见[M5设计](2026-10-23-m5-bounded-layout.md)及验收） | 拥挤样例可放或明确溢出；七件回放；当前自有图保存重开PASS |

M1 只重构不改行为；如果 M1 无法做到与基线一致，说明现有逻辑有隐藏耦合，先记录再处理，不边拆边改口径。

## 8. 不在本设计范围

- 任意剖面、详图、折弯展开、曲面板、型材和构件工序图仍属扩展范围；有限凸直边平板整边坡口的剖面实现与现场验收状态见[剖面设计](2026-10-26-native-sections.md)。
- 读取器、几何审计、`expressionRequirements.v1` 的规则内容。
- 公差、焊接和工艺要求的推断。
- 生产放行。PASS 仍只表示自动门通过。

## 9. 结构性决定汇总（2026-10-21 全部确认）

| # | 决定 | 结论 |
|---|---|---|
| 1 | 分层与边界 | 接受 P1～P6；布局不改方案；侧别由方案声明允许侧，OVERALL 与同列组锁定；接受 M2 后阶段性溢出 |
| 2 | 基准 | 每方向一条主基准，局部基准须由主基准定位；按车间图修订：主基准为包络极值边，v1 局部基准只允许对侧极值边；`HOLE_CENTER` 保留不启用 |
| 3 | 冗余 | `REFERENCE` 为一等概念；按车间图修订：v1 允许总尺寸、板身宽、对称两侧重复；图上暂不加括号 |
| 4 | 方案清单 | 每次生成、不阻断出图；重画附与上次已确认方案的变化对比 |
| 5 | 备选表达 | 契约支持，口径 v1 不启用；放不下先换比例图幅，仍不行溢出并作为案例 |
| 6 | 图纸模板 | 每批次从 Tekla 实时读取，存为批次模板快照，P4 只读快照；采集方式待 M4 只读 API 探测 |
| 7 | 车间图口径修订 | 以车间零件图为准：基准取极值边、孔链边到边闭合、相切直段不直接标、3 段起合并 `n@p`、整数显示、孔用 Tekla 螺栓符号。见第 10 节 |

具体取值（局部基准条件与上限、直接读数范围等）在 M3 作为口径参数讨论。各项细节与待解决问题见第 10 节。

## 10. 评审结论

### 2026-10-21 第 1 项：分层与边界（用户确认）

接受 P1～P6 分层和"布局不改方案"。决策归属如下：

| 决策 | 归属 |
|---|---|
| 标哪些尺寸、锚点、基准 | P2 方案 |
| 链式/坐标式、`n@p` 组合 | P2 方案 |
| 层级顺序、同列关系、有意冗余、孔组说明归属 | P2 方案 |
| 侧别 | P2 声明首选侧和允许侧；OVERALL 组与同列组锁定，孔定位、局部肩宽及普通轮廓链可在允许侧中由 P5 选择并记录。2026-10-23轮廓链就近选边及M5孔链换侧已实现，见[选边设计](2026-10-23-contour-chain-layout-side.md)、[M5设计](2026-10-23-m5-bounded-layout.md) |
| 层距、界线缩短、短尺寸文字和箭头外置 | P5 布局 |
| 孔说明代表孔与板内/板外、R 引注、零件号、厚度位置 | P5 布局 |
| 比例、图幅 | P4，可由 P5 失败触发有界重试 |

接受 M2 之后拥挤件阶段性转为 `LAYOUT_OVERFLOW`：溢出件不出图，只报告溢出对象，待 M5 改进。确需换标法的情况由第 9 节第 5 项（声明式备选）处理，不由布局自行决定。

### 2026-10-21 第 2 项：基准（用户确认）

- 每个方向恰好一条主基准（PRIMARY），总尺寸和板身尺寸从它出发。
- 允许局部基准（LOCAL），但局部基准本身必须由主基准出发的尺寸直接定位；方案记录 `locatedBy`，可读性门以 `RD_LOCAL_DATUM_UNLOCATED` 检查。
- 允许局部基准的具体条件（如孔排须落在该直边跨度内）和数量上限在 M3 作为口径参数确定。
- 主基准选取（用户确认）：按图面方向取左侧竖直、下侧水平的真实直边；包络上没有真实直边时，取离包络最近且跨度足够的相邻真实直边，仍没有则取圆弧极值点（轮廓真实点，不是虚拟交点）。车间下料靠边习惯确认后只改口径配置。
- 孔心基准（用户确认）：契约保留 `HOLE_CENTER`，口径 v1 不启用；出现真实需求时以案例启用。

### 2026-10-21 第 3 项：冗余尺寸（用户确认）

- `REFERENCE` 是方案中的一等概念，必须写明类别和理由。
- 同一方向上，尺寸构成的每个闭环至少含一个允许类别的 `REFERENCE` 组，否则 `RD_UNDECLARED_REDUNDANCY`。
- 口径 v1 只允许两类：总尺寸（OVERALL）和板身宽（BODY，如包住孔链的 190）。综合跨度（如"直段 + R 投影"的 120）不允许；其他类别以后以案例逐类放开。
- 图面暂不加括号，参考尺寸与普通尺寸显示一致；若以后需要区分，先验证 Tekla 2017 尺寸前后缀能力。

### 2026-10-21 第 4 项：方案清单（用户确认）

- 每件每次都生成方案清单，与图纸同批输出，不阻断出图。
- 重画时附与上次已确认方案的变化对比；确认后的方案摘要记入所有权登记。
- 针对新启用特征类型"先审后画"的开关留待以后，口径 v1 不做。

### 2026-10-21 第 5 项：备选表达（用户确认）

- 契约保留尺寸组的 `alternatives`（有序声明式备选），口径 v1 不启用任何备选。
- 放不下时先由 P4 在预算内换比例或图幅；仍放不下则 `LAYOUT_OVERFLOW`，该件作为案例收集，按特征类别再定备选（如坐标式、孔表）后写入口径。
- 启用备选后，选中的备选须写入方案清单与变化对比，并重跑 P3 方案门。

### 2026-10-21 第 6 项：图纸模板来源（用户确认：每次实时读取）

- 每次出图批次从 Tekla 实时采集图框、标题栏和表格占用区，不使用一次性标定的静态配置。
- 实现方式（用户确认）：采集结果作为"图纸模板快照"写入批次证据，P4 只读快照；历史快照用于回放和测试。
- 采集失败阻断该批次，不回退到写死的 45 mm 预留。
- 待解决：
  - Tekla 2017 API 能否直接读出标题栏/表格几何未核实；备选是在批次内用属性文件生成目标图后导出 DXF 实测占用区。M4 先做只读探测再定。
  - 图幅由布局决定，而占用区随图幅变化：采集需覆盖候选图幅，或在选定图幅后复核，具体在探测后定。
  - 车间单零件图属性文件名称待用户提供；提供前采集当前默认模板，快照标记未验收。

### 2026-10-21 车间图口径修订（用户确认，覆盖第 2、3 项部分内容及 R2.x 规则）

依据 车间零件图采集与逐点对照（8 件可对照）。用户确认 6 处差异全部以车间图为准：

1. **基准**：主基准取包络低端极值边（图面左侧、下侧）；尺寸链闭合到对侧极值边。口径 v1 的局部基准只允许对侧极值边（由总尺寸定位）。孔、轮廓转折都从极值边量，不从内部肩边或孔心量。覆盖第 2 项"主基准取左侧、下侧真实直边，无则取相邻直边或圆弧极值点"的选取方式：极值边本身没有真实直边时（如圆角、斜角落在包络上），按包络极值点定位，具体在 M3 用案例确定。
2. **相切直段**：不要求直接标出，由 R 与轮廓定位推出。覆盖 R2.2"R 旁短直段直接读数"。
3. **`n@p` 合并**：3 段及以上等距才合并；2 段相等分开标。
4. **显示精度**：整数（Tekla `NoDecimals`），内部保留原始双精度。覆盖现行 0.1 mm 显示（含 PR-15 显示 143.7 的历史认可）。
5. **冗余**：在总尺寸、板身宽之外，允许对称两侧重复（`SYMMETRIC`），如对称肩两侧各标一组。
6. **孔显示**：螺栓孔用 Tekla 螺栓符号（`Symbol2`，含孔和轴线），不再隐藏源螺栓、自绘孔边界和十字线。覆盖 R2.1 的源螺栓隐藏规则。Boolean 切割孔、无螺栓对象的孔仍需自绘；覆盖门需新增"螺栓符号"观测类型，读回核对符号显示属性。

车间图同时体现、作为口径 v1 默认的规律：孔链两端都闭合到对边（单孔也是）；孔阵按唯一行、列坐标各标一次，不同孔形可共用一条链；总尺寸两向都有、在最外层并与本方向特征链同侧；轮廓上的单个转折点从较近的极值边单独标；同一条边上的多个特征边到边成链；R 用原生半径尺寸，切点不另定位；链放在靠近特征的一侧。

未定事项：箭头实际显示（属性为 `NoArrow`，现行为实心箭头）未做图面核对，暂不改。

### 2026-10-21 1:1 交付模板（用户确认）

- 车间交付零件图就是 1:1 模板 `零件图10`：比例 1:1，图幅 2980×2110，字高 25（按 1:10 输出相当于约 A4、字高 2.5）。
- 口径 v1：P4 固定比例 1:1、图幅取模板快照值，不再按零件大小选比例；第 5 项“放不下先换比例图幅”在 v1 中只剩调整视图位置。
- P5 的纸面间距、文字框等量以 1:1 图纸单位计算，即模型毫米；层距、避让间隙按模板字高 25 的同一比例取值，M5 用车间图实测层距标定。
- 零件包络超出模板可用区时直接 `LAYOUT_OVERFLOW`，作为案例另定（例如是否允许换图幅模板），不自动缩小比例。
- 现行 R2.3 写图器按 1:2 等比例和 A3～A0 图幅工作，迁移前不改。

### 2026-10-27 放不下时选用比例

用户确认：1:1 放不下时可以放合适的比例。模板出图仍先试 1:1。主图连同标注放不进该模板可用区时，按 1、2、2.5、5、10、20、50 重排，取最小能放下的视图分母。模型侧的尺寸间距随这个分母放大，纸面间隙仍按字高。已经能 1:1 放下的零件保持 1:1。显式要求其他比例仍拒绝。比例 50 仍放不下则保持 `LAYOUT_OVERFLOW`，不换图幅，不删标注。有剖面时主图和剖面使用同一个分母。属性文件名里的“按 1 倍导出”不代表视图比例。

### 2026-10-21 M3b 轮廓规则（用户确认：规则 A）

轮廓转折点统一按边到边成链：每条轮廓单调链闭合到两侧极值边，跳过由 R 推出位置的切点，不直接标相切直段。车间图中"端部转折点单独从较近极值边标"的写法不采用。对称两侧相同的链只保留一条。可读性门改为阻断。实施与差异见 M3b 记录。

### 2026-10-21 同侧链合并（用户确认）

同一侧的轮廓链与孔链都边到边闭合时，合并为一条链，X/Y 两个方向一致，例如 T2-11P-226 顶部 115｜55｜3@80｜55｜15、右侧 20｜77｜65｜55。此写法不同于车间图（车间图分开标），属用户指定的口径。实施见 P6 离线记录。

### 2026-10-23 M4 实施补充

公开 PresentationModel 已实读图框、标题栏、材料表、说明。正式流水线准备目标自有图后采集实际模板，固定 1:1、字高 25，P4 输出可用区，替代写图器固定 45 mm。文字尚无精确字形框，采用明确标记的保守横/竖带；写前和保存重开后检查模板指纹及实际视图框。当前用户图纸保持打开时拒绝写入口。详见[M4设计](2026-10-23-m4-live-template-snapshot.md)。

本轮用户另授权修复 P2 多条闭合链重复内部坐标；按孔链优先、稳定顺序分配坐标归属，P3 阻断规则不放宽。详见重复坐标设计。
