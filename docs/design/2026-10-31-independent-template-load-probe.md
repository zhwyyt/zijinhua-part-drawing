# 独立模板加载探针与阶段0续作

日期：2026-10-31。依据：主方案 §3.5、§7 阶段0、T02/T03/T05。用户已要求继续下一阶段；本增量先完成可只读执行的模板加载核验，再安排新测试页的持久化试验。

## 目标与边界

模板采样中的图纸名称和候选文件相符，不代表 SDK 加载了该文件。新增独立 C# 加载探针、Python 核验器和离线命令，不修改旧工具、求解器或正式入口。探针仅在内存创建未 Insert 的 SinglePartDrawing 和 LayoutAttributes，调用 LoadAttributes；不打开、关闭、保存、修改或插入现场图纸，不调用模型/工作平面写接口。**现场已发现 SDK 加载旧格式属性会自动改写属性文件，不能把“没有显式写 API”称为完全只读。**

1. 核验显式模型身份和零件存在，保存 SDK 程序集、当前活动页元数据、工作平面及目标零件元数据；以候选 `.wd` 的绝对路径和属性名分别加载，并重复绝对路径加载。
2. 在连接前检查 `.wd`：含 `wdraw_dial.` 旧格式时整批阻断，输出 TemplateLoadPreflight.v1，禁止拿现场原件做迁移实验。其余输入先复制指定属性/伴随/布局文件到新输出目录，保留原字节摘要及属性目录文件名清单；每次构造和加载后检查摘要/新增或消失文件，变化立即停止后续调用/模板，不自动修复。增加随机不存在属性的负对照，SDK 回退默认值不得当作成功。
3. Python 独立对照研究报告绑定的 `.wd` 字节、模型身份、加载结果与实测图幅/图纸名称；同时保留失败和差异。文件快照必须可离线重放，变更或缺失使核验失败。
4. 接入 LayoutPreparation 作为补充证据；不得据此删除完整依赖、样式、实际图页应用、单位/缩短、占用、保存重开等门。

`.lay` 当前是二进制文件；可见字符串不能作为完整依赖解析。六份快照只称文件清单，不称依赖闭包。SDK 未提供实际解析路径时，名称加载与绝对路径返回相同只证明观测一致，不证明搜索路径唯一；负对照若未明确失败，身份门保持未通过。

## 状态与验证

原始 NativeTemplateLoadProbe.v1 记录真实调用结果、异常、前后状态和文件快照。`mutatingApiCalls=false` 只表示未调用显式原生写接口；属性是否保持不变必须核对全部文件前后摘要，不能由该标记推导。TemplateLoadStudy.v1 是可重放核验结果，始终 productionEligible=false；子检查为布尔值，顶层仍 STUDY_ONLY 或 INPUT_BLOCKED。不产生可执行 LayoutInput。

实际加载路径分开记录：SinglePartDrawing 的属性名构造能取得10/20/50名称和尺寸；绝对路径构造得到空名称/零图幅；独立 LayoutAttributes.LoadAttributes 返回 false 并保留287×200默认值。名称路径重复加载须一致，但名称返回正确仍不等于实际搜索路径已证明。旧格式自动转换期间捕获的20/50必须 INPUT_BLOCKED；恢复原文件后也不能倒改失败记录为通过。

本次20/50原件已按加载前字节快照恢复，转换后副本及恢复前当前哈希核对记录留存。SDK还为两模板各生成12份视图/尺寸属性，并增加dv.aDrawingViews引用；按创建时间确认属于本次加载后，24份文件已备份、核对哈希并从现场移除。18个已列原文件均与首次采样前摘要一致；未声明文件时间戳恢复，也不把属性文件回滚当作旧图纸恢复能力通过。后续迁移须在独立副本/隔离模型中验证语义与依赖，不能原地去前缀后重签既有研究报告。详见[验证记录](../verification/2026-10-31-independent-template-load-probe.md)。

反例至少覆盖错模型、错模板、文件缺失/篡改、同尺寸不同文件、加载失败、负对照回退、重复加载不一致、现场状态改变、伪造生产资格、未知/重复模板及补充证据错绑。现场重复读取用于验证本探针的状态稳定，不升级为实体数值噪声基线。
