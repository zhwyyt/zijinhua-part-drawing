# M5 有界布局求解

## 范围与不变量

接续已确认的P1～P6架构及轮廓链就近选边。当前缺口是尺寸文字未参与PLAN碰撞、说明只贪心试放、无回溯预算、失败只给字符串。M5不修改P2尺寸组/顺序/锚点/值/组合/参考角色。保持固定1:1、实际模板及原有字高；不得缩字号、删标或改锚点求通过。普通轮廓和孔定位允许两侧，总尺寸及同列组锁侧。同列尺寸作为一个布局单元整体移动。

## 模块与算法

- `native_layout`负责将固定方案转成原生命令及有序候选，原有分层仅提供稳定首选位置，不再作为合格结论。
- `layout_solver`独立执行有限候选深度优先搜索，维护已放置文字框、尺寸/界线/引线；后续对象失败时回退已放对象并换候选。每件最多4096次候选检查，尺寸每侧最多8层，说明候选也有固定上限；顺序固定，无随机数。成功记录候选、碰撞检查和预算；失败抛出携带报告的 `LayoutOverflow`，包括对象、碰撞对象、失败原因、已用预算和是否耗尽。流水线保存该报告且不进入写图。
- 尺寸候选只改变Distance/Up，按附近侧优先、原层优先、逐层外移、再允许的另一侧。总尺寸在同侧所有特征层外，同列组保持共同线位。候选中不改组合与文字表达。
- 编号从材料内候选点按净距稳定排序；孔说明用真实孔的近侧锚点和板内/四侧候选；厚度/规格在原位置及邻近四侧候选；原生半径保留真实三点，在有限Distance候选中选择。说明与尺寸共同搜索，不能只逐条贪心。
- 每次接受候选前检查文字框交叠、尺寸线穿字、引线跨尺寸/界线及其他引线、材料内编号、可用纸面包络。文字与其自身引线/自身尺寸为预期连接。Tekla文字背景对界线的裁断属于显式渲染行为，仍在保存后按实际DXF验证剩余线段，不能用计划当见证。
- 原生半径候选先于可移动线性尺寸预留；尺寸按孔/直段在内、总体在外的稳定顺序搜索。同侧重叠区间必须保持此层级，不得因避让反转。搜索报告的 `conflicts` 是最多32条被拒候选的历史，不代表SOLVED结果仍有未解决冲突。
- P4对当前包络选择实际模板内可用矩形，失败回溯其他布局候选；固定1:1不变，不擅自换图幅。有限搜索无解或预算耗尽明确溢出，不声称数学上不存在任何布局。

## 文字几何与读回

使用Arial字体度量取代字符数乘常数。字号、旋转、`n@p`组合分别进入尺寸文字框。Tekla自动外置短尺寸的确切位置并非离线可知：用明确标记的保守范围覆盖中间/两端候选，不把预测框叫作SDK实测框。原生半径同样保守建模；实际保存后的SDK/DXF字形框为最终依据。PLAN报告包含所有占用框与度量来源，来源/字体缺失阻断，不静默猜字体。

读回继续逐组核对实际Up/Distance、真实锚点和值，并核对同列、总尺寸层级和实际文字是否落在承诺的布局范围内。通过覆盖不能掩盖布局失败。先用M4保存证据标定字体和原生文本偏置，再以独立拥挤案例验证回溯/换侧/溢出，最后同一自有第1页保存重开验收。

## 验证计划

1. 冻结七件历史基线、当前现场方案，内容不变检查先于布局比较。
2. 失败先行：尺寸文字拥挤、后续固定对象迫使早期候选回退、孔链允许侧换侧、锁侧/同列/总体外层、预算耗尽、模板放不下以及长编号等。
3. 固定输入重复结果一致，源事实/方案不变，四向变换及比例仅影响布局；每个失败保留具体冲突对象。
4. 全部现有测试、七件回放、十件车间案例、质量/安全扫描，结果与变化列表归档。
5. 当前模型仅定位登记的自有试验图，无活动图时API执行保存重开、实际SDK/DXF图面与源重查；不枚举目录、不操作原车间图。

安全边界不变：求解器纯离线数据运算，不增加网络、进程、文件路径执行能力；预算限制搜索量。新增Python模块使用现有项目设计/验收文档体系，不建立第二套文档。

## 实施与实测边界

实现在 `layout_solver.py`，正式流水线将成功或失败的报告写为 `layout-<partId>.json`。历史非模板离线回放仍可选旧图幅。正式入口必须实时模板。2026-10-27 起，1:1 放不下时按比例序列放大视图分母，见[架构补充](2026-10-21-native-planning-architecture.md)；仍不换图幅、不缩字号、不删标。

半径的最终文字方向由Tekla控制，当前以弧中点周围的有限占用范围参与保守规划，并用实际字形读回复核。短尺寸首尾按对应端外置、内部短尺寸保守覆盖候选位置；密集内部短段可能被阻断。这是明确的有限求解边界，不保证任意几何都可自动排布，也不以增加预算掩盖范围错误。
