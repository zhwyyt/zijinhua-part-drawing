# Tekla 平板零件图

把模型证据转成可检查的原生标注。先读 [平板规则](references/rules.md)；实际操作 Tekla 2017 时再读 [API 经验](references/tekla-2017-api.md)。修正规则或处理相似失败时对照 [验收案例](references/verification-cases.md)。

本 skill 提供规则与执行流程；配套项目已实现确定性的加工表达要求、布局、原生写图和保存重开读回，使用`draw-native-parts`，见 [可执行表达引擎与出图](references/expression-engine.md)。执行代码随项目维护，不复制进skill。不得把案例编号、坐标或临时脚本当成通用规则，也不得把有限样例通过描述为任意平板全自动生产能力已验证。

新原生路线已有独立 R1 读取器、R2a 来源/NC 审计和 R2b 有限类型解析/证据核验，先读 [原生读取](references/native-reader.md)。COMPLETE、CANDIDATE 或 EVIDENCE_MATCHED 都不等于精确成品已证明；R2 成品证明未通过前不能进入自动写图。

r2b.8已将简单平板孔槽与Boolean切割统一为`materialFinalState`，并通过`plan-native-expressions`直接生成加工表达要求。用户已确认螺栓孔必然贯穿、栓钉仅表面焊接不成孔；按[平板规则](references/rules.md)执行，不再为这两项重复索取孔壁证明。0.1 mm模型预算与原始双精度保留，规则依据不冒充精确BREP。

Tekla 2017 按逐特征证据充分性决定准入，NC 按需补充。先核验原生证据，再判断缺口能否由 NC 补足；当前模型编号有效时，NC 按精确零件编号归属，同号不同实例可共享；日志 GUID 保留追溯，不要求与所读实例相同。展开 NC 是有效加工信息，原形定位所需的坐标对应单独核验。查看 `featureEvidence`、`evidenceSufficiency`、`nativeSource` 和 `ncSource`，不能以 NC 成功替代孔作用或切割终态证明。

确认螺栓孔仍需有效目标关联和孔形参数。孔形用该组自己的槽孔参数；圆孔是槽增量为 0 的同一写法 `n*D宽度(总长x宽度)`。已提供且对不上的 NC 仍阻断。Bolt=false仅开孔体核验自身形状与目标板厚两面。独立孔观察作为可选补充，已有矛盾保留；不从尺寸、符号或计划反造观察。STUD保留附件来源但不生成孔表达。

## 执行流程

1. **读取与定界**：检查当前仓库说明、可用 Tekla 接口和版本。获取用户选中零件或已明确指定的 ID，核对模型身份、精确 partPosition、已有图纸及锁定/下发状态。选择为空时可继续使用本会话已授权的 ID，不猜选其他零件。保留原工作平面。只分析时不写图。
2. **独立列特征**：从最终实体、孔组作用关系和图纸对象建立特征清单，先于标注计划生成。记录坐标系、轮廓边/圆弧、厚度、全部孔、尺寸/方向、切割以及证据来源；冲突和缺项不可静默过滤。按规则判断适用性。
3. **要求先行、规划后置**：先调用表达引擎，从独立事实生成必须表达的信息，核对 READY/BLOCKED；不得由已生成标注反推要求。再为每项要求绑定尺寸、两向定位、必要方向和中心线，使用 PLAN 观测核查覆盖；先定真实基准及锚点，再安排内外尺寸层、引线、编号和表格避让。复用已验收规则，无需重复请求用户确认。未覆盖类型只阻断受影响零件，其他已授权零件继续。若当前环境没有项目引擎，明确报告不可运行，不能以口头自检冒充机器审计。
4. **执行**：优先使用项目`draw-native-parts --out <新批次目录>`，省略`--ids`读当前选择；已授权ID可显式传入。沿用同一`--ownership`登记，更新需名称、模型、实例和页号一致；发现人工标注或锁定/冻结/下发拒绝更新。仅操作自有`NATIVE-PLATE-R1`图。没有配套代码时明确不能运行，不复制固定样例坐标。圆弧/Boolean件采用原生解析曲线表达核验终态、保留隐藏目标Part关联，定制图形需随来源变化重建。
5. **保存与验收**：保存、关闭、重开，重新读取尺寸值、锚点、样式、可见对象，转换为 READBACK 观测交给表达引擎核查覆盖，不得复制要求中的期望值充当读回。再检查原生图面中的真实文字、箭头、线段、轮廓及标题栏。可用 API 导出/预览就直接验证；无法取得图面证据时标记 VISUAL_PENDING，不用对象数量或表达层 PASS 代替图面验证。
6. **交付**：逐件报告图纸标记、比例、实际修改、各质量门状态和未通过项，附读回/图面证据位置。更新规则时同时留下失败案例、人工期望、证据字段和回归记录。不得把自动完成率与已验收图纸正确性混为一谈。

## 本项目操作约定

- 用户要求通过 API 操作，不接管鼠标键盘。确实只能使用界面时先说明原因并提示，取得当前有效授权后才能操作；不得静默回退到桌面自动化。
- 已授权的生成、修正和重复处理不反复问许可；规则与 skill 整理本身不需要修改现场图纸。
- 默认实心箭头；板内只放精确零件号，不带引线、规格或材质。后续用户明确改变样式时以新要求为准，并记录覆盖范围。
- 模型变化会使文字半径引注和定制界线失效；重新读取并重建，不声称这些辅助对象天然关联模型。
- 必需标注放不下必须BLOCKED，当前批处理无自动重排重试。自动图面PASS仅覆盖已实现的文字重叠/穿字线、纸面边界与表达；标题表、中文字体和完整审美仍须按实际证据说明，不冒充生产放行。
- 规划R2按轮廓特征链、可信R关系和附近真实孔基准选择尺寸，肩宽就近放置、孔说明优先板内。保存重开核对缩短界线，并检测引线跨尺寸/界线；不能因覆盖完整就接受坐标全标或长界线堆叠。见[规则](references/rules.md)和[P-116回归](references/verification-cases.md)。
- R2.1补完整孔排两端边距、板身宽外置及可直接读取的R旁直边长度；等距组合保留两端界线。已确认的螺栓孔保留可见符号，位置对不上的组仍隐藏；保存重开核对完整属性，不以 hidden 单项代替符号属性验收。
- R2.2要求R旁短直段也直接读数，不以尺寸小省略。实际平直长度优先于“直段+R投影”的间接尺寸，避免现场减法；短尺寸排版与完整性分别核验。
- R2.3对所有轮廓区间按“实际分段同列、圆角处断开、总体在外”规划。用真实直段及相邻R证据替换冗余综合跨度；独立尺寸集保留真实间隔，整列避让。保存重开核对实际层距与方向，不能只验数值。

## 可复用输出契约

使用现场现有 JSON/日志格式即可，无需另造同义 schema，但至少保留：

- `source`：模型身份、零件 ID/partPosition、读取时间、几何版本或指纹、坐标变换、数值容差。
- `features`：独立几何清单；每项有稳定来源标识、类型、真实几何、证据与歧义。
- `annotations`：来源特征、实际锚点、实测值/显示值、文字、样式、视图/纸面位置、对象所有权。
- `coverage`：逐特征的形状/大小、X/Y 定位、方向、中心线要求及实际对象映射，不能只统计计划对象。
- `verification`：几何、覆盖、保存重读、图面四项分别为 PASS/FAIL/PENDING；附原因和证据。全 PASS 才可写本图验收通过，仍不等于生产下发授权。
